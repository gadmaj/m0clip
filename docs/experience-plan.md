## Published cycle 4: truthful asset loading

Main-thread and worker transfers share a generation-scoped byte ledger. Concurrent
files add to the same total rather than replacing one another. MB means decoded
HTTP asset payload, including HTTP cache; preview assets, unpacked ZIP contents and
subsequent blob/IndexedDB reads are not counted as new transfers. Native script
resource timing fills observable gaps without counting instrumented fetches twice.
The discovered total is a known minimum, not a promised fixed dependency graph.

The themed bar uses actual known bytes. Unknown decoded lengths stay indeterminate;
recent observed throughput estimates only current downloads. Stalled data retires
the estimate. Decode, compilation and material preparation remain separate, and
only the existing simulation/visual/rendered-frame gate completes the bar.
Late progress cannot replace a canonical error or unlock failed entry. Explicit
entry stops observation without cancelling application downloads.

Typecheck, production build and the permanent concurrent/unknown/generation/rate
ledger regression passed. Native HTTP consumer smoke also passed independent clone
bodies counted once, BYOB reads, streaming WebAssembly, unread HTTP errors and
stop-with-in-flight consumption. No observer-only tee or full-body buffer was added.

Dedicated headed Chrome qualified all ten cold/warm/concurrent/unknown/gzip/stall/
disconnect/error/recovery/mobile behaviors across nine passing main-run cases and
the corrected isolated unrecoverable-disconnect case—not one green ten-case run.
Real pointer, keyboard and touch moved Pong while bytes arrived; RAF advanced,
recording opened a real take and timeline playback advanced. Complete unfiltered
map galleries fit both 320 and 390 pixels. Successful cases had no page or network
errors. The 104-second live video and representative screenshots were inspected.

## Product direction

A small, immediately interactive launch screen; map → character → load → play.
The scene is the main interface. Advanced robotics and capture tools remain available
without covering the scene by default. Simplification removes presentation bulk,
not capabilities or native map detail.

### Proposed launch flow

1. Show only the compact map chooser. Fetch shell, catalog metadata and small
   thumbnails, not simulation/runtime assets. No Pong during selection.
2. Preselect **Ghost (`nt_ghost_ctg`)** for a fresh visit. A valid shared view or
   explicit map/body link takes precedence; offer a clear way to resume the last
   scene rather than silently overriding the fresh-visit default.
3. Choose a character using visual cards. Separate the character's appearance from
   its physics/controller. Existing R1, G1, Go2, variants, policies and imports stay
   reachable. Show optional model download size and compatibility where known.
4. **Load scene** commits the selection and starts only its required assets. After
   more than 30 seconds of unfinished loading, morph the centered bar into Pong,
   not a separate window. Support keyboard, pointer and touch without a game result
   or extra physics, WebGL or neural-runtime dependencies.
5. Show aggregate known download progress, downloaded/total **MB** (decimal bytes),
   estimated remaining time and a short phase label. Distinguish download ETA from
   compile/decode/preparation. Unknown totals/ETA say so; never invent a percentage.
   Avoid counting cached data, ZIP contents and subsequent blob reads as new downloads.
6. Announce readiness only after simulation, selected character, complete map visuals
   and a usable first frame are ready. Stop/cancel Pong immediately and offer
   **Enter scene** without waiting for the morph or requiring game interaction.

Keep errors, selected scene identity and retry visible. Loading a new selection must
not let stale callbacks replace it or erase an error. The current map-only visual
retry and saved-view/capture readiness protections remain.

## Orchestrated implementation workflow

The first research wave used three read-only workers: loading/performance,
interface/capture, and character/physics/customization. Their source-backed findings
are synthesized here; no feature code or runtime benchmarks were produced by them.

Before implementation, one integration owner fixes these shared contracts:

- **Selection:** map id, exact physics robot/model, controller/policy and cosmetic
  character id are separate. Valid share links override fresh-visit defaults.
- **Loading:** a generation-scoped asset ledger plus explicit initialization phases;
  selected dependencies, known/unknown bytes, cached sources, errors and readiness.
- **Appearance:** retain exact part names and existing serialized six-region keys;
  character descriptors declare supported plants, presets and optional asset needs.
- **Captures:** stable capture id, binary motion chunks, project metadata and an
  atomic saved-state contract. Keep existing take files readable.

Then run file-disjoint work streams in parallel, integrate, and verify once:

| Stream | Ownership and boundary | Integration proof |
| --- | --- | --- |

## Baseline findings and remaining constraints

- Before cycle 1, `src/main.ts` eagerly started the renderer/worker and the typed
  intro hid the running load. The current `src/start.ts` keeps this heavy graph
  behind an explicit launch choice; the obsolete intro was removed.
- Before cycle 1, robot files loaded sequentially after runtime initialization.
  `src/sim/engine.ts` now overlaps runtime/manifest and uses four ordered in-flight
  loads, draining pending work on errors before retry/model switching.
- The old policy store reread all cached weights at worker startup. The working
  metadata/payload split removes unselected reads while preserving imports.
  The aggregate 214,854,099-byte ZIP is not the boot download.
- Selected map visuals start after the worker publishes its model. Earlier transfer
  can overlap compilation while preserving scene/resource ownership and cleanup.
- `src/render/scene.ts` readiness promises remain canonical; `src/loading/` now
  combines observable main/worker payloads. An exact full-scene ETA is still unknown.
- `src/render/robot-kit.ts` already implements Original/Tinbot/Orbit/Prism, six
  mixable regions and restoration/disposal. These are render-only replacements,
  not cheaper physical plants. Semantic part overrides are needed for names such
  as Go2's `base_link`; do not invent absent parts on different variants.
- `SceneView.pickPart` and `LookPanel.select` already support live part selection.
  A separate preview must use its own camera/rectangle while keeping the same
  part identities, paint and module state.
- The pre-library baseline kept recording state in RAM; stopping another take
  replaced `App.take`. The private Shots candidate now persists independent takes,
  PNGs, camera/range/appearance edits and committed interrupted-recording prefixes.
- Existing `.take.zip` files do not embed map/model/policy assets. New physical
  topology and model revisions need compatibility handling, not name matching.
- `docs/source-robot-models.md` records native rig limits. Dog already has supported
  R1 retargeting; the static connected girlbot needs authored segmentation/skinning
  for full-body articulation. No fake nearest-joint articulation as a quick fix.
- Other noclip.website games use different formats. Current supported import is
  Source BSP conversion; broader game support is a separate adapter effort with
  collision, asset-format and distribution constraints.
- Cycle 16 removes safely redundant Ghost previews. The next startup investigation
  should measure the remaining native restoration/GLTF construction work before
  changing it; preserve authored mip levels and exact pixels.
- The dock labels the physical robot while an authored character can be visible.
  A future identity refinement should distinguish those roles without introducing
  another appearance state or losing deliberate live/review preferences.
